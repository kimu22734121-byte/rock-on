# rock-on — 録音まとめ

会議や講習会を録音すると、**文字起こし → Claude による議事録・講義ノート作成** までを自動で行うアプリです。
次の 2 つのアプリでできています。

| アプリ | URL | 役割 |
|---|---|---|
| 📱 **録音アプリ**（スマホ用 PWA） | https://kimu22734121-byte.github.io/rock-on/ または PC の `/rec/` | 録音・「ここ重要」マーク・自動送信・まとめの閲覧 |
| 🖥 **まとめサーバー**（PC で動かす） | `/` | 文字起こし（Whisper）・要約（Claude）・PC 用の画面 |

```
 スマホ（iPhone / Android）                  PC（Windows など）
┌──────────────────────┐   HTTPS   ┌──────────────────────────────┐
│ 録音アプリ /rec/        │ ───────▶ │ まとめサーバー                  │
│ ・録音（5秒ごとに端末保存）│  音声送信  │ ・faster-whisper で文字起こし   │
│ ・★ここ重要マーク        │ ◀─────── │ ・Claude API で要約            │
│ ・まとめを見る・共有      │  要約取得  │ ・data/ に保存                │
└──────────────────────┘           └──────────────────────────────┘
```

## 録音アプリ（スマホ）の機能

- **録音の種類を 4 つから選べる**（種類によってまとめ方が変わります）

  | 種類 | 向いている録音 | まとめの内容 |
  |---|---|---|
  | 🗣 会議 | 会議・定例・打ち合わせ | 議題ごとの議論、決定事項、ToDo（担当・期限）、持ち越し課題 |
  | 📚 講習会 | 講習会・セミナー・授業 | トピック別の内容、重要ポイント、用語集、質疑応答、復習のヒント |
  | 💬 会話 | 面談・電話・インタビュー・相談 | 話題ごとの内容、相手の要望、約束したこと、次にやること |
  | 📝 その他 | 上のどれにも当てはまらないもの | 内容に合わせた形。「まとめ方の希望」（例：3 行で、手順書の形で）も書ける |

- **ワンタップ録音**：一時停止・再開、録音レベル表示、録音中は画面が自動で消えない
- **★ ここ重要マーク**：押した時刻を記録。要約でその前後を重点的にまとめ、「重要マーク箇所」の節を作る。タップでメモも付けられる
- **停止したら自動送信**：サーバーに音声を送ると、文字起こしと要約が自動で始まる
- **データを失わない**：
  - 録音は 5 秒ごとにスマホ内（IndexedDB）に保存
  - 電波がなくても録音でき、つながったら自動で送信
  - 送信に失敗したら「記録」タブから再送できる
  - アプリが落ちても、次に開いたときに「送信」または「続きを録音」ができる
- **中断からの自動再開**：iPhone でバックグラウンドに回ってマイクが止まっても、アプリに戻ると続きから録音。中断前後の録音はサーバーでひとつにつながる
- **まとめを見る**：要約・文字起こし・重要マーク・録音の再生、コピーや共有（LINE・メールなど）

### 録音済みのファイルからまとめる

録音アプリの「📁 録音済みのファイルからまとめる」（PC 画面ではファイル選択）から、すでにある音声や動画を送れます。
会議・講習会の切り替え、タイトル、要約の方法は、録音するときと同じ設定が使われます。

- 使える形式：m4a / mp3 / wav / aac / ogg / webm、動画の mp4 / mov など（動画は音声だけを使います）
- **複数のファイルを選べます**。「1 つの記録としてつなげる」をオンにすると、講習会の前半・後半のように分かれたファイルを 1 本としてまとめます（ファイル名の番号順）。オフにすると、ファイルごとに別の記録になります
- iPhone のボイスメモを使うとき：ボイスメモで録音を選び、共有ボタン →「"ファイル"に保存」で保存してから、録音アプリで選んでください
- Android のレコーダーアプリの録音は、たいてい「ファイル」アプリの Recordings などのフォルダにあります

### 画面ロック中の録音について（重要）

ブラウザの制限で、Web アプリは画面ロック中の録音を保証できません。

| | 画面ロック・アプリ切り替え時 |
|---|---|
| Android（Chrome） | 多くの機種で録音が続く |
| iPhone（Safari） | 止まることがある → アプリに戻ると自動で続きから録音（中断中の音声は入らない） |

**長い会議では、画面をつけたままにしておくのが確実です**（録音中は自動で消えない設定になっています）。
完全なバックグラウンド録音が必要になったら、この Web アプリを Capacitor でネイティブアプリ化する方法があります。

## セットアップ（Windows）

1. [Python](https://www.python.org/downloads/) をインストール（3.12 以上。インストール画面で **「Add python.exe to PATH」にチェック**）
2. このフォルダの **`start.bat` をダブルクリック**
   - 初回は必要なライブラリを自動でインストールします（数分）
   - Claude API キーを聞かれます。持っていれば貼り付けて Enter、**なければ何も入力せずに Enter**（要約は claude.ai に貼り付ける方法になります）。`config.env` に保存され、次回からは聞かれません
3. 「まとめサーバーを起動します」と表示されたら準備完了。PC のブラウザで http://localhost:8000 を開けます

| ファイル | 役割 |
|---|---|
| `start.bat` | サーバーを起動（初回セットアップ込み。止まっても 10 秒後に自動で再起動） |
| `setup_autostart.bat` | PC にサインインしたとき自動で起動するように登録 |
| `remove_autostart.bat` | 自動起動の登録を解除 |
| `config.env` | API キーなどの設定（`config.env.example` を参照） |

**つけっぱなしの PC で使う場合**：`start.bat` で一度起動できたことを確認してから `setup_autostart.bat` を実行してください。
自動起動はサインイン後に動くので、PC が再起動したときにサインイン画面で止まらないよう、Windows の自動サインインを設定しておくと安心です。

Mac / Linux では次のように起動します。

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export ANTHROPIC_API_KEY=sk-ant-...
uvicorn app.main:app --port 8000
```

## 要約の方法（2 種類から選べる）

録音アプリ・PC 画面の「要約の方法」で選びます。文字起こしはどちらも PC 上で自動・無料です。

| | ⚡ 自動（API） | 📋 手動（claude.ai） |
|---|---|---|
| 費用 | 従量課金（1 時間の会議で約 40 円） | 無料（claude.ai の無料プランで OK） |
| 手間 | 録音を止めるだけ | コピー → claude.ai に貼り付け → 回答を貼り戻す |
| 必要なもの | Claude API キー | claude.ai のアカウント |

**手動の流れ**：録音後、記録の画面に「claude.ai で要約する」が出ます。
① 「指示と文字起こしをコピー」→ ② 「claude.ai を開く」で新しいチャットに貼り付けて送信 → ③ Claude の回答をコピーして貼り付け、「要約として保存」。

- API キーが設定されていないと、自動は選べません（グレー表示）
- 自動で要約に失敗したとき（クレジット不足など）も、手動の方法で要約できます
- 手動で作った記録を、あとから「Claude API で自動要約」で作り直すこともできます

### Claude API キーの取り方

1. https://platform.claude.com で登録
2. **Billing** でクレジットを購入（先払い、最低 5 ドル）
3. **API Keys** →「Create Key」で作成し、表示された `sk-ant-...` をコピー（一度しか表示されません）
4. `config.env` の `ANTHROPIC_API_KEY=` に貼り付け（`SKIP_API_KEY=1` の行があれば削除）、`start.bat` を起動し直す

## 録音ファイルはどこに保存される？

**① 録音中〜送信まで：スマホの中**
- 録音アプリのデータ領域（ブラウザの IndexedDB）に 5 秒ごとに保存されます。写真アプリやファイルアプリには出てきません
- まだ送信していない録音は、録音アプリの「記録」タブ →「送信待ち」に表示されます
- **サーバーに届いた時点で、スマホ内の録音は自動で削除**されます（スマホの容量を圧迫しないため）

**② 送信後：まとめサーバーの PC の中**

`start.bat` があるフォルダの中の `data` フォルダに、録音ごとのフォルダが作られます。フォルダ名は録音を送信した日時です。

```
rock-on\
└─ data\
   └─ 20261120-143005-a1b2c3d4\   ← 2026/11/20 14:30:05 に送信した録音
      ├─ audio_000.webm           録音（iPhone は .m4a）
      ├─ audio_001.webm           途中で中断・再開した場合の続き
      ├─ transcript.txt           文字起こし
      ├─ summary.md               要約（メモ帳で開けます）
      └─ meta.json                タイトル・重要マークなどの情報
```

- 録音アプリや PC 画面から、録音の再生・要約や文字起こしのダウンロードもできます
- 不要になった記録は、このフォルダごと削除してください
- **バックアップしたいときは `data` フォルダをまるごとコピー**してください

## スマホから使う（HTTPS 化）

スマホのブラウザでマイクを使うには **HTTPS** が必要です。いちばん簡単なのは **Tailscale**（個人利用は無料）です。
自分の端末どうしだけをつなぐので、**外部の人からはアクセスできず安全**で、外出先からも使えます。

1. PC とスマホの両方に [Tailscale](https://tailscale.com/download) を入れて、同じアカウントでログイン
2. Tailscale の管理画面（https://login.tailscale.com/admin/dns）で **MagicDNS** と **HTTPS Certificates** を有効にする
3. `start.bat` でまとめサーバーを起動したまま、別のコマンドプロンプトで:

```bat
tailscale serve --bg 8000
```

4. 表示された `https://<PC名>.<xxxx>.ts.net` に `/rec/` を付けて、スマホで開く
   例: `https://my-pc.tail1234.ts.net/rec/`
5. ホーム画面に追加すると、普通のアプリのように使えます
   - iPhone：Safari の共有ボタン →「ホーム画面に追加」
   - Android：Chrome のメニュー →「アプリをインストール」または「ホーム画面に追加」

> ⚠ このアプリにはログイン機能がありません。`--host 0.0.0.0` やポート開放でインターネットに直接公開しないでください。

## GitHub Pages から録音アプリを開く

録音アプリは GitHub Pages にも置けます。決まったアドレス **https://kimu22734121-byte.github.io/rock-on/** で開けるようになります。
文字起こしと要約は、これまでどおり PC のまとめサーバーで行います。GitHub Pages は画面のファイルを配るだけで、録音・文字起こし・要約・API キーは PC の外に出ません。

**最初の 1 回だけ（GitHub の設定）**
1. GitHub でこのリポジトリを開き、**Settings** →（左のメニュー）**Pages**
2. **Build and deployment** の **Source** を **Deploy from a branch** にする
3. **Branch** で、録音アプリのあるブランチ（`main` にまとめていれば `main`）と、フォルダ **`/docs`** を選んで **Save**
4. 1〜2 分待つと、上に `https://kimu22734121-byte.github.io/rock-on/` が表示されます

**スマホでの使い方**
1. スマホの Tailscale をオンにして、`https://kimu22734121-byte.github.io/rock-on/` を開く
2. 最初に「設定」画面が出るので、まとめサーバーのアドレス（`https://PC名.xxxx.ts.net`）を入れて「接続して保存」
   - アドレスは、PC で `tailscale serve status` を実行すると表示されます
   - Android の Chrome で「ローカルネットワーク上のデバイスへのアクセス」の確認が出たら **「許可」**
3. ホーム画面に追加すると、普通のアプリのように使えます

アドレスはあとから右上の「⚙ 設定」で変えられます。PC の `/rec/` から開いた場合は、設定なしでそのまま使えます。

**しくみ**：まとめサーバーは、`ALLOWED_ORIGINS`（既定は `https://kimu22734121-byte.github.io`）のサイトからの接続だけを受け付けます。
ほかのサイトから録音や要約を読み取ることはできません。リポジトリ名やユーザー名を変えた場合は、`config.env` に `ALLOWED_ORIGINS=https://新しいユーザー名.github.io` と書いてください。

## 設定（環境変数）

| 変数 | 既定値 | 説明 |
|---|---|---|
| `WHISPER_MODEL` | `medium` | `small`（軽い）/ `medium` / `large-v3`（高精度、GPU 推奨） |
| `WHISPER_DEVICE` | `auto` | `cpu` / `cuda` / `auto` |
| `WHISPER_COMPUTE_TYPE` | `default` | GPU なら `float16`、CPU で軽くするなら `int8` |
| `CLAUDE_MODEL` | `claude-opus-5-5` | 要約に使う Claude モデル |
| `ALLOWED_ORIGINS` | `https://kimu22734121-byte.github.io` | 録音アプリを置いたサイト（GitHub Pages）。カンマ区切りで複数可 |

初回の文字起こし時に Whisper モデル（medium で約 1.5GB）が自動でダウンロードされます。

**処理時間の目安（1 時間の録音）**：CPU + medium で 30〜60 分ほど、GPU + large-v3 で数分。
CPU で速くしたいときは `WHISPER_MODEL=small` と `WHISPER_COMPUTE_TYPE=int8` を試してください。

## 使い方のコツ

- 「補足」欄に **参加者名・専門用語** を書くと、文字起こしと要約の両方で固有名詞を正しく認識しやすくなります。
- 要約で API エラーが出ても、文字起こしは保存されています。「要約をやり直す」で要約だけ再実行できます。
- スマホは話者の近く（机の中央など）に置くと、認識精度が上がります。

## うまくいかないとき

**「処理に失敗しました」と出た**
録音は PC の `data` フォルダに保存されています。記録を開いて **「やり直す（文字起こしから）」** を押すと、録り直さずにやり直せます。
エラーの文章に、原因と次にすることが書いてあります。

| エラーの内容 | すること |
|---|---|
| 文字起こしモデルのダウンロードに失敗 | PC のインターネット接続を確認して「やり直す」（初回だけ約 1.5GB をダウンロードします） |
| PC のメモリが足りない | `config.env` に `WHISPER_MODEL=small` と書き、`start.bat` を起動し直して「やり直す」 |
| 録音ファイルを読み込めない | 録音が短すぎるか、ファイルが壊れています。録り直してください |

NVIDIA の GPU がある PC で GPU 用の部品が足りない場合は、自動で CPU に切り替えて文字起こしを続けます。

## 構成

```
app/main.py           まとめサーバー（受付・ジョブ管理・結果配信）
app/transcribe.py     faster-whisper による文字起こし
app/summarize.py      Claude API による要約（会議 / 講習会 / 会話 / その他、重要マーク反映）
static/index.html     PC 用の画面（録音・アップロード・結果表示）
docs/                 スマホ用 録音アプリ（PWA）。GitHub Pages と PC の /rec/ の両方から配る
  index.html          画面と録音処理
  sw.js               オフライン起動用 Service Worker
  manifest.webmanifest, icon-*.png
data/<日時-ID>/       録音・文字起こし・要約の保存先（git 管理外）
```

### API（録音アプリ ⇔ サーバー）

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/config` | 自動要約が使えるか（`api_available`） |
| POST | `/api/jobs` | 録音を送信（`audio` 複数可、`kind`, `title`, `notes`, `marks`(JSON), `client_id`, `summary_mode`=`auto`/`manual`） |
| GET | `/api/jobs` | 一覧 |
| GET | `/api/jobs/{id}` | 状態・要約・文字起こし・マーク |
| POST | `/api/jobs/{id}/resummarize` | Claude API で要約（やり直し・手動からの切り替え） |
| GET | `/api/jobs/{id}/prompt` | claude.ai に貼り付ける用のテキスト |
| POST | `/api/jobs/{id}/summary` | claude.ai で作った要約を保存（JSON `{"summary": "..."}`） |
| GET | `/api/jobs/{id}/audio/{n}` | 録音（n 番目のパート） |

`client_id` が同じ送信は二重登録されません（通信が切れて再送しても安全）。
